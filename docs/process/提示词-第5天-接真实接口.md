# Task 2 · 修 httpAdapter 的 8 个缺口（接真接口的前置）

我已逐行核过 `adapters/httpAdapter.js`。按严重度排序，前 3 条不修，第 5 天联调必炸。

## P0 必修

**G1 · 所有请求不带会话标识**
`/session/actions`、`/session/state`、`/session/accept`、`/session/summary`、`/session/random-check`、
`/session/reset` 全都没有 session id。多会话场景后端无法定位是哪一局。
要求：新增 `CONFIG.sessionId`，从 `window.DIPLOMAT_CONFIG` 或 URL query `?session=` 读取；
统一通过一个 `withSession(path)` 拼到查询串，或由 `buildRequest` 放进请求体——
**具体承载方式先实现成可切换的单一函数**，并在代码注释标 `// TODO 待A确认: session_id 承载在 query / body / header`。
不要在多处各拼一次。

**G2 · 错误映射会把服务端故障伪装成"行动不合法"**
两处 bug：
- `request()` 的 catch 把网络不可达返回成 `{error:"SESSION_BUSY"}`（约 L133）。
  后果：前端按 SESSION_BUSY 契约**自动重试 1 次**，并显示"会话正被另一笔行动占用，请求排队中"。
  实际是服务挂了，重试无意义且文案在骗人。
- `mapError()` 在 `payload` 为 null 时返回 `INVALID_ACTION`（L72-74）。
  后端 500 返回 HTML 时 `JSON.parse` 失败 → `body=null` → 判成"该行动不满足条款约束"。

要求：
- 新增一个**传输层状态**，不要伪装成业务错误码：网络不可达 / HTTP 5xx / 响应不是合法 JSON，
  三种情况走同一条"服务不可用"通道：不自动重试、保留草稿、toast 文案写
  「服务暂不可用，草稿已保留」，并原文附 `status` 与响应前 200 字符。
- 业务错误码仍严格按契约：6 码做专门 UI，**其余码走行内红条并原文渲染 detail，禁止 else 静默**（K2 已回签）。
- 契约 v1 里 A 已修订：**错误码不是 6 码全集**，真实是引擎 17 码 + API 层码，
  以 `Huawei/API错误码清单.md` 为准。该文件我本地没有，**遇到就先按"未知码不阻塞"实现**，
  并在回复里提醒我去找 A 要这份清单。

**G3 · `blankState()` 被 mock 的硬编码污染**
`blankState()` 调 `mock.createState()` 后只重置了 `version:0`、`clauses:[]`、`cards:[]`、`phase:"loading"`，
但 mock 的 `createState()` 里 `round:3`、`maxRound:6`、`ap:3`、`apMax:5` 全都留着。
后果：真实首帧拿到状态前，界面显示的是第 3 轮的模拟数字——**这正是"数字不同源"的破口**。

要求：`blankState()` 显式给出全部业务字段的**空态**，初值只能是中性值
（`round:1`、`ap:null`、`version:0`、条款空数组），并在渲染层保证：
业务字段为 null 时显示占位符「—」而不是 0，**不得用 0 或 mock 值填充未知**。
这条要在页面上可验证：真实模式首屏顶栏轮次应显示 `R?/6` 或骨架，而不是 `R3/6`。

## P1 今天修

**G4 · 中文条款名当协议键**
`toOfferPatch()` 用 `c.name`（如"监测站点数量"）作 `offer_patch` 的 key，
`toPatch()` 又用 `open_issues.indexOf(c.name)` 反查。B 换议题后条款名变化，映射即断，
且 `open_issues` 若给的是 id 就永远匹配不上、条款全部显示为 decided。

要求：改用 `c.id` 作键；同时保留一份 `id → name` 映射给请求体需要名字的场合。
**后端到底收 id 还是 name，实现成适配层内一个可切换函数**，注释标 `// TODO 待A确认`。
`open_issues` 匹配写成"同时接受 id 或 name"的宽容解析，并在不匹配时把该条款标 `unknown` 而不是静默 decided。

**G5 · `summary()` 是假成功**
现在返回 `{ok:true, timeline: state.timeline}`，把本地数据回传，后端响应完全被忽略。
要求：真正消费响应；后端返回为空时明确显示「本轮总结未返回内容」的空态，
不得拿本地 timeline 冒充后端结果。注意 K3=B 已裁决：提交本轮总结**只记录、不推进轮次、不扣 ap**，别改。

**G6 · `reset()` 丢弃新状态**
现在 `.then(function(){ return blankState(); })` 完全不理响应。
要求：若后端返回新状态就消费它，否则显式说明"reset 后需重新 GET /session/state 才能拿到条款"，
并真的补这一次 GET。现在 reset 完条款是空数组，报价板会空掉。

**G7 · `nextTopic()` 没有消费者**
返回 `r.body` 原样，但没人用它重建 `clauses`／事实依据／隐藏任务／态势。换议题会残留上一局数据。
要求：在适配层写清切题后的完整状态重置路径，**议题切换失败时必须保留原场景、不覆盖当前进度**
（手册 7.1 议题条硬要求）。

**G8 · 150 秒超时无中间反馈**
`TIMEOUT_MS=150000` 是 P5 回签值，**不要改**。但提交按钮会卡 2.5 分钟没反应，违反
"任何按钮点击后都必须有反馈，失败不得静默"。
要求：保留 150 秒硬超时，加一个 **10 秒软提示**——10 秒未返回时在提交按钮旁显示
「上游仍在处理，已等待 12s…」，草稿仍保留，用户可主动取消。
这条要在页面上能演示，是 Demo 的证据点之一。
