## 三、任务卡

### 卡 A · 复盘页面（第 8 天主功能）

```text
（此处粘第二节的「通用上下文头」）

【任务】
现在终局弹窗只有一句结论 + 一句指标提示，点「查看战报」打开的是报价板弹窗（openReport），
没有独立复盘页。请新建复盘页面，把「谈判结果 / 协议质量 / 学习表现」三维评价、教练终局建议、
关键转折、未决条款处理、证据跳转和数据来源声明放进同一个可截图、可复盘的界面。
这是手册 §5.2「终局判定与评价必须分开」和 Demo 分镜镜头 10 的硬要求。

【落点】
1. 新建 src/domain/debrief.js：
   - export function buildDebrief(state) 返回：
       outcome / quality / learning   直接复用 buildReportSummary(state) 的三维数据，不另算
       verdict                        store.judge 的 { reason, title, summary, metricsHint }
       turningPoints                  从 state.actions + state.log 取最多 4 条关键行动
                                      { round, label, version, kind }
       unresolved                     state.clauses 中 status 为 pending / open / rejected 的条款
       evidence                       { action_id, round, kind, clause, label }，
                                      逐条校验 action_id 在 state.actions 可查、clause 在 state.clauses 有同名、
                                      round 在 1..maxRounds —— 任一条不成立则整条丢弃（教练契约 §1.3 断言 1）
       dataSource                     固定文案：「本页数字来自本局结构化状态；模型解说仅供参考，不构成事实。」
   - speaker_score 相关字段若 state 中不存在，一律返回 null，由组件显示「终局评价待接入」。
   - 不许在此文件里重新计算收益、红线或终局判定。

2. 新建 src/components/DebriefPage.js：
   export function DebriefPage({ debrief, coach }) → 返回完整 HTML 字符串，分区顺序固定：
   ① 终局横幅：五态标题 + kicker + summary（沿用 ENDGAME_COPY 文案与 tone 配色）
   ② 三维评价：谈判结果 / 协议质量 / 学习表现，三块并列，各 2 行指标，无值显示 '—'
   ③ 教练复盘：speaker_score 四维评分条 + feedback；null 时显示「首轮不计分」或「终局评价待接入」，
      不画 0 分条；items[] 按 kind=stage / alternative 分组，默认折叠
   ④ 关键转折：turningPoints 列表，点击可跳轮次（data-action="debrief-jump" data-round=…）
   ⑤ 未决条款：unresolved 列表，标明 pending/open/rejected 与 changedVersion
   ⑥ 证据链：evidence 列表，点击高亮条款或跳对话；无有效证据时显示「暂无可追溯证据」
   ⑦ 数据来源声明：固定在页脚 dataSource 文案，不得裁掉
   所有区块使用现有 .chip / .status-strip / .drawer 类族，不新造配色；黑金主题不变。

3. src/main.js：
   - 新增 renderDebrief() 与 openDebrief()：
     openDebrief() 调 modal.open({ title:'终局复盘', kicker:'DEBRIEF', content: DebriefPage(...) })；
     primary:'查看报价板' → openReport()；secondary:'关闭'。
   - 修改 renderEndgame() 的 primary 从 openReport 改为 openDebrief，文案改为「查看复盘」；
     **保留 openReport() 函数与「查看报价板」入口**，不删除报价板弹窗。
   - actions 增加 'open-debrief' / 'debrief-jump' / 'toggle-debrief-section'；
     debrief-jump 复用 jumpToRound(round)，跳完关闭弹窗并把对话滚到对应轮次。
   - 终局打开时若 store.state.coach 里已有终局建议则直接渲染；没有就显示占位，
     不发起阻塞请求、不重试轮询。

4. 隐私过滤：渲染 coach 文本前，按 coach-contract §「不得出现」清单过滤
   对方红线 / 真实 BATNA / 真实底线 / 隐藏任务 / net_gain 等关键词；
   右栏对方态势只出现估计值与可信度，不复述真值。

【规则】
- 三维评价的数据只能来自 buildReportSummary(state)，不许在组件里重算或加权。
- 教练建议引用具体行动；evidence 任一断言失败整条不渲染，不许「尽量显示」。
- 复盘页默认展开 ①②⑦，③④⑤⑥ 可折叠；不抢占主流程焦点。
- 终局自动推演已在第 7 天停止；本卡不得重启自动推演或改动 autoPlay 状态。

【验收】
- 造一局走到终局（完整协议 / 部分协议 / 主动退出 / 僵局 / 轮次用尽各测一次）：
  五态标题与 ENDGAME_COPY 一致，三维评价均有真实值或 '—'。
- 首轮 speaker_score 为 null 时显示「首轮不计分」，页面上不出现 0 分条、不出现 NaN。
- 点击关键转折跳转到对应轮次，对话与版本号同步；无残留终局遮罩。
- 注入一条 action_id 不存在的 evidence：该条不渲染，其余条目正常。
- 注入含「对方红线」字样的教练文本：该句不出现；对方态势只有估计值。
- 1440×900 与 1920×1080 下七区块无横向滚动，数据来源声明可见。
- 截图存 docs/evidence/day8-debrief-*.png，至少含五态之一 + 首轮 null + 证据跳转三张。
- vite build 与 build-single.mjs 均通过，单文件版终局复盘可用。

【禁止】
- 不许编造评分、收益或「胜率」；不许把三项指数直接等同于谈判胜负。
- 不许删除或改写 ENDGAME_COPY / judgeEnd() / openReport()。
- 不许在复盘页暴露对方私有底牌或内部地址、密钥。
- 不许把 debrief 请求接入提交链路的 await。
```
