## 三、任务卡

### 卡 A · 自动推演视图（第 7 天主功能）

```text
（此处粘第二节的「通用上下文头」）

【任务】
在谈判页加一个「自动推演」控制视图：用户点开始后，系统按「我方提交 → 对方回应 → 规则结算 →
下一轮」逐步推进，并在界面上留下可截图的推演日志。核心要求来自团队共同约定：必须等待上一轮
完成并渲染后再继续，禁止用固定间隔强推。

【落点】
1. src/stores/NegotiationStore.js 增加：
   state.autoPlay = {
     active: false,
     mode: 'step' | 'continuous',     // 单步 / 连续
     speed: 1,                         // 1 / 1.5 / 2，只影响下一步启动前的等待
     pendingRound: null,               // 等待结算的轮次
     startedAtRound: null,
     steps: [],                        // { round, label, version, at, status }
     lastError: null
   }
   方法：startAutoPlay(mode)、pauseAutoPlay()、stopAutoPlay()、setAutoPlaySpeed(n)、
        recordAutoPlayStep(step)、clearAutoPlaySteps()。
   注意：autoPlay 不得绕过 store.lockRound() 与 ROUND_LOCKED 判定。

2. 新建 src/components/AutoPlayPanel.js：
   export function AutoPlayPanel({ autoPlay, round, ended, phase }) → 返回
   <div class="autoplay-panel" id="autoPlayPanel">…</div>
   包含：开始 / 暂停 / 单步 / 停止 四个按钮，速度三档，状态文字
   「自动推演 R3 → R4 · 等待对方回应」「已暂停（人工接管）」「终局已停止」，
   以及可展开的「推演日志」（渲染 autoPlay.steps）。默认折叠日志，不占主画面。

3. src/main.js：
   - 在 renderRound() 或 renderStatusStrip() 之后新增 renderAutoPlay()，把 AutoPlayPanel 挂到
     会场顶部状态带下方，传 store.state.autoPlay。
   - actions 增加：'autoplay-start' / 'autoplay-pause' / 'autoplay-step' /
     'autoplay-stop' / 'autoplay-speed' / 'toggle-autoplay-log'。
   - 在 submitTurn() 成功链路里：对方回应 appendSpeech(reply) 且 renderStrategy / renderRound /
     renderMetrics 全部执行后，调用 onRoundSettled(turn.round)；该函数只在
     autoPlay.active && !store.state.ended && phase==='ready' && 版本号已更新 时安排下一步。
   - 安排下一步用 requestAnimationFrame + 一次 setTimeout，超时时长 = 基础 400ms / speed，
     绝不写 setInterval 轮询推回合，也不缩短现有 650ms 的 replyTimer。

4. 人工接管：监听用户主动操作（toggleStrategy、base-action、条款下拉 change、end-turn），
   只要 autoPlay.active 就立即 pauseAutoPlay() 并 toast「自动推演已暂停，人工接管」。

5. 停止条件：终局（judge 有值）、ROUND_LOCKED、任意 error、用户点停止 —— 任一条命中都
   stopAutoPlay()，并在推演日志里记 status:'stopped' + 原因，不自动重试。
   SESSION_BUSY 的 3 秒倒计时保持原有独立链路，不并入自动推演。

【规则】
- 自动推演只调用现有 submitTurn()，不另造后端请求、不伪造对方台词、不改 state.round。
- 每一步必须在推演日志中留痕：轮次、动作标签、版本号、时间戳、状态。
- 教练异步结果照旧不进 await，不能阻塞下一轮。
- 控制条样式复用现有 .status-strip / .chip / .ghost-button，不新造配色；黑金主题不变。

【验收】
- 点「开始（连续）」后连续推进 4 轮；每一轮的对方发言都出现在会场，且顶栏 / 报价板 /
  协议抽屉三处版本号一致。
- 控制台执行 store.state.autoPlay.steps.length 等于实际推进轮数。
- 点「暂停」后不再产生新轮次；再点「单步」只推进一轮。
- 推进中点任意策略卡或改条款：自动推演暂停并 toast 提示，草稿保留。
- 注入 ROUND_LOCKED 后自动停止，日志写明原因；不触发无限重试。
- 终局时自动停止并弹出终局卡，控制条显示「终局已停止」。
- 1440×900 与 1920×1080 下控制条与日志不造成横向滚动。
- vite build 通过；build-single.mjs 产出的单文件版双击打开不白屏，控制条可用。

【禁止】
- 不许用 setInterval 固定三秒连发。
- 不许绕过轮次锁、幂等键、六错误码分支。
- 不许改 ActionBar / ClauseBoard / StatusStrip / CoachPanel 的已验收视觉与逻辑。
- 不许把自动推演接到真实大模型或网络请求。
```
