# 第 2 天 · 发给 CodeArts Agent（码道）的提示词

## 用法

1. 在码道里打开 `11.11` 这个文件夹（IDE 或 Space 模式均可），让它先读 `docs/ia-design.md` 和 `index.html`。
2. 把下面**提示词正文**整段粘贴进智能体对话框，一次发全，不要拆句发。
3. 提示词里已要求它**每完成一个 Task 就停下来等确认**。看到 T1 产出的 `docs/state-contract.md` 后，先发给 A 和 C 评审——M1 里程碑要求"当晚完成跨模块评审，不能带着含糊字段进入开发"。评审通过再让它继续 T2。
4. 建议用智能体（Agent）模式而不是问答模式，并开启 Codebase 索引，让它真的读到现有代码而不是凭想象重写。

## 提示词正文

````text
# 你的角色

你是 Diplomat 项目的前端工程智能体，服务对象是团队成员 D（负责 UI、教练 Agent 与 Demo 统筹）。
这是一个 10～12 天的比赛 MVP，D 每天可投入 4～6 小时。你的产出必须当天可运行、可截图、可评审。

# 项目背景

Diplomat 是一个 AI 外交谈判训练系统，正在从旧版（对话多、报价不结构化、终局难判断）改造为
新版「黑金战情室」：中央结构化报价系统 + 版本化协议 + 规则审计 + 教练 Agent 复盘。

D 的终极责任两条：
1. 保留旧版黑金战情室的气质和情报信息量，把新报价系统自然嵌进去，不为报价板牺牲对方态势与情报入口。
2. 教练反馈不打断谈判；并把团队成果剪成一条评委能看懂的演示。

# 已冻结的上游决策（先读，不要重新发明）

请按顺序完整读取本仓库以下文件，读完再动手：
- `docs/ia-design.md`：信息架构已定稿。含八区域拆解、主闭环状态机、错误码→UI 行为映射、
  数据一致性约束、教练 Agent 评分契约、旧版资产逐屏处置、15 条验收自检。
- `index.html`：第 1 天已产出的单文件可交互原型（约 1200 行，零外部依赖）。已实现三视图
  （报价／对话／情报）、报价板、矮版行动预演、协议抽屉、终局复盘、6 个错误码模拟、幂等键拦截。
- `docs/demo-storyboard.md`：Demo 分镜。

上面这些文档里的结论是**已经评审过的决策**，不是建议。与你的习惯冲突时，以文档为准。

# 本次要做的三个 Task（严格按顺序，每做完一个就停下来给我确认，不要一口气全做完）

## T1 · 状态字段契约冻结（最高优先级，M1 里程碑验收项）

把散落在 `index.html` 里的 `S` 状态对象和错误处理，抽成一份可以发给 A／B／C 三人评审的字段契约，
输出到新文件 `docs/state-contract.md`。要求：

1. 逐个字段列出：字段名、类型、取值范围／枚举、**由谁产出**（A 会话后端／B 场景与模型／
   C 规则与审计／D 前端本地）、**前端是否可写**、为空时的 UI 表现。
2. 覆盖这些既有能力对应的字段（字段名以 `index.html` 现状为准，不要改名）：
   回合与最大轮次、版本号 `version` 与服务端版本 `serverVersion`、行动点、草稿 `draft`、
   已选卡牌、幂等键与 `submittedKeys`、重试键、条款集及其 `status`（含 `pending`）、
   我方态势、对方态势（估计值 + 可信度）、外交渠道及冷却、隐藏任务、双方 BATNA、
   突发事件与随机议题检查状态、`speaker_score`、连接态。
3. 单独一节写清**接口形状**：一轮提交请求需要携带哪些字段（至少 `action_id`／幂等键、
   当前 `version`、`round`、条款变更、所选卡牌），响应可能返回的 6 个错误码及各自的
   `error` + `detail` 示例 JSON。
4. 单独一节列「**需要 A／C 在第 3 天前确认的开放问题**」，把我无法自行决定的字段歧义全部摊开，
   一条一行，写清「问题／我的默认取值／如果不同会导致什么」。
5. **不得新增任何文档里没出现过的错误码或错误字段。**后端错误格式已定，只有 `error` 和 `detail` 两个字段。

产出后停下，等我确认 A／C 的评审结果，再进行 T2。

## T2 · 前端框架化改造（为第 5～6 天接真实接口做准备）

把单文件 `index.html` 重构成分层结构。目标不是炫技，是解决三个具体问题：
状态改一处要翻 1200 行、模拟逻辑和渲染逻辑缠在一起、第 5 天接真接口时无处可换。

要求：
1. 拆成清晰的三层，目录自定但要简单：
   - **状态层**：唯一的 store（对应现有 `S`），字段集中定义，暴露读／订阅／提交三类方法。
   - **数据适配层**：一个 `mockAdapter` 和一个 `httpAdapter`，实现同一套接口签名。
     现在全走 mock；第 5 天只换实现、不改调用点。**这是本次改造唯一必须拿到的收益。**
   - **渲染层**：按区域拆组件（顶栏、议题条、左栏四块、中央三视图、预演、右栏五块、
     协议抽屉、手牌、覆盖层），全部只读渲染，禁止在组件内部计算金额、比例或加权分。
2. 引入构建工具可以，但**必须保留一条命令本地起服务**的验收方式，并在 `README.md` 写清启动命令。
   团队 A 每天要求「主分支都有一个可启动版本」，任何人 clone 下来必须 30 秒内能跑。
   不允许出现只有我本机 IDE 能跑起来的状态。
3. 重构过程**功能零回退**：三视图切换、报价板编辑、卡牌选择、行动预演、提交与幂等拦截、
   6 个错误码路径、协议抽屉冲突合并、终局复盘与四维评分——第 1 天已有的行为必须全部等价保留。
4. 改造完，在浏览器控制台打印一份当前完整状态快照，作为可截图的过程证据。

## T3 · 高保真定稿（设计 token 抽离 + 双断点像素校验）

1. 把配色、字体、间距、层级从散落的 CSS 里抽成一份 token（对应现有 `:root` 变量并补全）。
   主金固定 `#c9a227`（旧版双金并存已收敛，不要再引入 `#C5A059` / `#D4AF37`）；
   衬线字体只用于大标题，正文无衬线——这是旧版「情报感」的主要来源，比颜色更关键，不可改。
2. 逐条把 `ia-design.md` 第 8 节验收自检里标为「待实测」的条款转成可复现的检查项：
   在 1440×900 与 1920×1080 两档下，主报价板、行动预演、手牌、终局入口必须同屏可见且无横向滚动。
   给我一份「检查项 → 操作路径 → 预期」的核对表，我要截图放进交付材料。
3. 补齐交互态的视觉细节：加载骨架、空场景、失败、超时、重复点击、版本冲突、终局只读。
   硬性要求：任何按钮点击后都必须有反馈，失败不得静默。

# 不可违反的约束（违反任一条即返工）

1. **所有数字同源**：只有状态层一份真值，三栏与抽屉只读渲染，前端不得二次计算金额或比例。
2. **版本号三处一致**：顶栏、报价板底部、协议抽屉全部渲染同一个 `version`，不留独立副本。
   绝不能出现「报价板 V4、协议抽屉显示 V3」。
3. **失败不改草稿**：任何错误分支都不得清空 draft。
4. **重试复用幂等键**：TIMEOUT／SESSION_BUSY／VERSION_CONFLICT 合并后重提，一律同一个 key；
   已入账的 key 二次提交直接拦截提示，不得重复记账、不得产生两笔相同行动。
5. **模型故障不阻塞报价**：MODEL_UNAVAILABLE 只让左栏解说与情报视图降级为空态，
   报价板与预演必须照常工作。
6. **教练评分口径写死**：四维权重 `position_clarity` 30%／`diplomatic_tact` 30%／
   `emotional_control` 20%／`substance_quality` 20%；评级 90-100→S、70-89→A、50-69→B、
   30-49→C、0-29→D。总分与四维分由服务端返回，前端只做展示与评级映射，**不得本地重算加权、
   不得新增维度、不得自行解释区间**。第 1 轮对方未发言时 `speaker_score` 必须为 `null`，
   UI 显示「首轮不计分」，不填 0、不生成替代分数。
7. **教练建议不阻塞下一轮**：异步生成、默认折叠；不得泄露对方私有底牌。
8. **对方信息永远不是真值**：整块加「估计值」横幅，每个数值带估计标签与可信度百分比；
   对方 BATNA 恒显示「未知」，无线索时不得填充估计值伪装成信息。
9. **未决条款不可被签署**：检测到 `status=pending` 时接受按钮 disabled，并在按钮上方列出
   未决条款编号与原因。
10. **参数口径固定**：轮次 `R3/6`，行动点上限 5、当前 `3/5`，三视图名称就叫「报价／对话／情报」，
    条款 5 条。不得改回旧版的 15 轮和 2 点上限。
11. **范围锁定，不扩写**：不做多边谈判重构、观战模式、25 个议题全部知识化、复杂关系矩阵、
    谈判树全树、突发事件模态弹窗、精致动画、真实国际事件预测。
    任何"要不要加个 XX"的想法一律不实现，在回复里单独列成「建议但本轮不做」给我，我自己判断。
12. **不编造收益**：行动预演里的预计值必须标注为预演，不得提前写成实际收益；
    终局只呈现状态里的实际数值；模型生成内容单独标注来源。
13. **机密零泄漏**：不得写入任何真实 API Key、Token、内部地址、个人配置。
    需要密钥的位置一律用环境变量示例文件（`.env.example`，值写成占位符）。
14. **禁止大改视觉风格**：黑金战情室气质已全员评审过一次，本轮不再重开风格讨论。
    不要换主题色、不要改成浅色、不要加渐变卡片和圆角玻璃拟态。

# 工程规范

- 分支：只在 `feat/ui-coach-d` 上工作，不要碰 `main`。
- 提交信息用 `feat:` / `fix:` / `test:` / `docs:` 前缀，说明改了哪个模块。
- 每次改动后清理临时文件和缓存，不要提交大文件、录屏原片、`node_modules`。
- 保留过程证据：关键改动要能看出「改前是什么样、问题是什么、改完是什么样」，
  我要截图放进交付材料，不要最后一天补拍。

```

【当前阻塞】          ← 需要 A/B/C 谁在什么时间前处理什么

# 最后

不要给我一份"计划"就结束，我要看到实际文件改动。
也不要一次性把 T1+T2+T3 全做完——先只做 T1，产出 `docs/state-contract.md` 后停下等我。
````

## 为什么这么排（给你自己看的，不用发给码道）

- **T1 是第 2 天真正的死线**。手册 M1 里程碑 = 第 2 天接口冻结，未通过的后果写得很明确：
  「不能带着含糊字段进入开发」。你第一天已经把页面做出来了，风险不在 UI，在于 `index.html` 里的
  字段是你一个人定的、A/B/C 没见过。所以 T1 的产出物是**发给别人评审的东西**，不是代码。
- **T2 不做第 5 天会返工**。第 5 天写的是「接真实接口」，第 6 天「修 UI 状态同步」。
  1200 行单文件直接对接真接口，等于第 6 天全砸在改结构上，联调窗口（第 6～9 天）就被吃掉了。
  适配层（mock/http 同签名）是这次重构唯一的硬收益。
- **T3 顺手做**。双断点实测第一天就是「待实测」，一直挂着；第 9 天要冻结 UI，越早暴露越好。
- 提示词里那 14 条约束不是啰嗦，是把 `ia-design.md` 已经定的结论**前置到生成之前**。
  码道这类智能体最容易做的事就是自作聪明加维度、换配色、顺手把评分逻辑重算一遍——
  那几条正是手册里点名禁止的。
