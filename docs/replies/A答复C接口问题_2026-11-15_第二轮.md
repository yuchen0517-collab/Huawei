## Q1：接受协议走哪个接口 / action_type？

走统一的 `POST /session/{session_id}/action`，`action_type` 传 **`"accept"`**（schema 枚举已含，无独立 accept 路径）。约束：

- `offer_patch` 必须为 `{}`（schema 的 allOf 强制：非报价类行动 `maxProperties: 0`）；
- `expected_effect`／`public_message` 必填，`conditions` 可带（会并入协议条件清单，去重）；
- 引擎语义：accept 立即封存协议。agreement 取双方最新报价逐条款合并（**对方最新报价优先覆盖**），条款全覆盖 → `FULL_AGREEMENT`；未全覆盖按场景 `terminal_rules.partial_agreement_allowed` 判 `PARTIAL_AGREEMENT` 或 `DEADLOCK`；
- 场景开 `accept_requires_no_open_issues`（默认真）且仍有未决条款时，引擎以 400 `INVALID_ACTION` 拒绝；
- 终局读响应 `status === "ended"`（无独立 ended 布尔字段）。

## Q2：全量投影里条款可选值的形状？

**现状：投影中没有条款可选值清单。** 投影固定 9 字段：`session_id / round / phase / my_offer / opponent_offer / open_issues / action_history / status / mode`。

条款合法取值目前只在场景文件里：

- 枚举型：`clauses[].options[{id, score}]`，前端取 `id` 字符串数组；
- 数值型：`issues[].range{min,max,step}`（B 芯片场景即此型，`option` 允许数值，schema 中 option 类型为 string|number）。

这是 P12 已记录缺口，A 承诺第 5 天联调前补入投影，建议形状：

```json
"clauses": [
  {"name": "全球算力资源分配", "type": "enum",
   "options": ["自愿分享", "附带可核查机制", "市场主导"], "initial": "自愿分享"}
]
```

补入前的过渡方案：前端按场景静态映射选项；提交时 `offer_patch` 键为议题名、值必含 `option` + `note`（见第一轮答复 G4）。

## Q3：action_points 的字段名与形状？

- 引擎内部：`state.action_points` 为**整数**（每行动固定扣 1 点；每轮重置为场景 `action_points_per_round`，默认 3，场景可配）。
- **当前 API 投影未暴露**（P8 已回签：A 第 5 天前补入）。计划形状：

```json
"action_points": {"current": 2, "max": 3}
```

未补入前前端不要从投影读该字段，按「每轮 3 点、每行动 1 点」口径展示。契约中 `apMax=5` 的旧假设作废，以投影 `max` 为准。

## Q4：终局 speaker_score 的字段名与四维结构？

服务端**目前未实现** speaker_score（投影无此字段，引擎无此产出）。契约 §5 的四维为前端口径，作为后续接口对齐基准：

| 字段 | 权重 | 说明 |
|---|---|---|
| `speakerScore.total` | — | 0–100 整数，服务端取整 |
| `speakerScore.position_clarity` | 30% | 立场清晰度 |
| `speakerScore.diplomatic_tact` | 30% | 外交辞令 |
| `speakerScore.emotional_control` | 20% | 情绪控制 |
| `speakerScore.substance_quality` | 20% | 实质内容 |
| `speakerScore.feedback` | — | 20–40 字，先亮点后问题 |

对方未发言的轮次必须为 `null`（不填零分）；评级映射（≥90 S／70–89 A／50–69 B／30–49 C／0–29 D）由前端做。本轮不出接口，终局面板按 null 态渲染。

## Q5：debrief 202 是否包含教练建议 / 复盘文本？

**纯受理，不含内容。** `POST /session/{session_id}/debrief` 返回 HTTP 202 + `{"status": "accepted"}`，无复盘文本、无教练建议。`coachAdvice` 本轮只保留前端折叠占位（P15 已回签），生成链路另提 backlog。

## Q6：scenario_id / agent 合法默认值；session 并发与过期策略

开局请求体（`CreateSessionRequest`，extra 字段禁止）：

```json
{"scenario_id": "ai_governance", "agent": "us", "scenario_path": null}
```

- `scenario_id`：当前唯一合法默认值 **`"ai_governance"`**。传 `scenario_path` 加载 B 场景时，`scenario_id` 必须等于场景文件内的 id（如 `scn_chip_001`），不一致 → 400 `INVALID_SCENARIO`。
- `agent`：当前唯一合法值 **`"us"`**，其余 → 400 `INVALID_AGENT`；我方固定 `cn`（服务端注入，前端不传 actor）。
- 并发：会话级互斥锁（`mutation_lock`），同一 session 同时只处理一轮；并发提交 → 409 `SESSION_BUSY`，允许**同键**自动重试 1 次后转手动。不同 session 互不阻塞。
- 过期：**内存存储，无 TTL，无主动清理**；服务重启即全部失效，旧 session_id 一律 404 `SESSION_NOT_FOUND`，前端引导重新开局。无心跳接口（P14），连接态由前端本地派生，唯一真实信号是 409 `SESSION_BUSY`。

## Q7：my_offer.offers[name] 的值是否含 option / note / options？

只含 **`option` + `note`** 两个键，**不含 options**：

```json
"my_offer": {
  "version": 3,
  "offers": {
    "全球算力资源分配": {
      "option": "附带可核查机制",
      "note": "我方立场调整为附带可核查机制的分配方案。"
    }
  }
}
```

开局无报价时为 `{"version": 0, "offers": {}}`。`opponent_offer` 同构。全局 `S.version` 取 `max(my_offer.version, opponent_offer.version)`，`base_version` 提交时取该值（契约 §1 表后注）。

## Q8：500 INTERNAL_ERROR 前端按「服务不可用」展示（不自动重试、保留草稿）是否接受？

**接受。** 500 是未捕获异常兜底，形状固定 `{"error":"INTERNAL_ERROR","detail":"服务内部错误，请稍后重试。"}`，代表服务端 bug，自动重试无意义；保留草稿与 I2 不变量一致。请与以下两码区分：

- 503 `MODEL_UNAVAILABLE`：业务降级码，置 `modelDown=true`，报价板不受影响，不自动重试；
- 409 `SESSION_BUSY`：唯一允许自动重试的码（同键 1 次）。
