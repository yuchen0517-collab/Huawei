## G1：session_id 承载方式与路径

放 **path**，不放 query / body / header。多会话共用同一组路径，用路径段区分：

| 方法 | 路径 | 用途 |
|---|---|---|
| POST | `/session` | 开局，响应直接返回 `session_id` 和初始全量状态投影 |
| GET | `/session/{session_id}/state` | 拉取全量状态投影 |
| POST | `/session/{session_id}/action` | 提交一轮行动 |
| POST | `/session/{session_id}/auto_step` | 自动步进（调试用） |
| POST | `/session/{session_id}/debrief` | 复盘受理（202） |

注意：会话为内存存储，服务重启即失效。任何带旧 session_id 的请求返回 **404 `SESSION_NOT_FOUND`**，detail 为「会话不存在或服务已重启，请重新开局。」前端此时应引导重新开局。

## G4：offer_patch 键与 open_issues

都用**议题名**（中文条款名），不用条款 id：

- `offer_patch` 键为议题名（如 `"全球算力资源分配"`），值必含 `option` + `note`；前端负责 `c1..c5` → 议题名的映射（P1 已回签）。
- `open_issues` 返回议题名数组（引擎 `_refresh_open_issues` 直接取 `clause_names`）。
- `my_offer.offers` / `opponent_offer.offers` 的键同样是议题名。
- 条款 id（`c1..c5`）仅是前端本地草稿键，不出现在线上报文中。

## G2：错误统一处理

- 服务端所有错误响应统一形状 `{"error": "<code>", "detail": "<中文人类可读文案>"}`，**文案全部由服务端定**，前端原文渲染，禁止 else 分支静默。唯一例外：409 `VERSION_CONFLICT` 额外携带 `current_state`。
- HTTP 映射现状：

| HTTP | 错误码 | 含义 |
|---|---|---|
| 400 | `INVALID_JSON` / `INVALID_ACTION` / `INVALID_SCENARIO` / `INVALID_AGENT` + 引擎 17 码大部分 | 请求体非法 / 行动被规则拒绝 |
| 404 | `SESSION_NOT_FOUND` / `NOT_FOUND` | 会话不存在（或服务重启）/ 路径不存在 |
| 405 | `METHOD_NOT_ALLOWED` | 方法不允许 |
| 422 | `INVALID_REQUEST` | 请求体字段校验失败（缺字段、类型错误） |
| 409 | `VERSION_CONFLICT` / `SESSION_BUSY` / `DUPLICATE_ACTION` / `PHASE_CLOSED` | 版本冲突 / 会话忙 / 重复行动 / 已结束 |
| 503 | `MODEL_UNAVAILABLE` | 模型不可用，本轮未推进 |
| 500 | `INTERNAL_ERROR` | 未捕获异常兜底 |

- 「网络不可达 / 请求未到服务端」不会产生服务端 `status` 字段，属前端本地派生态（TIMEOUT 由前端 150 秒计时产生），不要当成服务端业务码。
- **409 `SESSION_BUSY`**：允许前端自动重试 1 次（**同键**），之后转手动（契约 6.4 已冻结，不变）。
- **503 `MODEL_UNAVAILABLE`**：仍按业务降级码处理——前端置 `modelDown=true`，不自动重试，报价板不受影响（契约 6.4 已冻结）。

## K1：409 VERSION_CONFLICT 的 current_state

保留。响应在 `{error, detail}` 之外额外携带 `current_state`，内容与 `GET /session/{id}/state` 完全相同的全量状态投影（含 `my_offer`／`opponent_offer`／`open_issues`／`round`／`phase`／`status` 等）。前端用它刷新基线版本后**同键**重提。

## 鉴权

当前实现**没有任何鉴权**：不校验 `Authorization`，也不需要 `X-Session-Id` 头（session_id 已在路径中）。`DEEPSEEK_API_KEY` 仅为服务端环境变量，与前端无关，前端不需要注入任何密钥。如演示后需加鉴权，另提 backlog，本轮不加。

## CORS

由 **A（api.py）** 配置，已挂 CORSMiddleware：`allow_origins=["*"]`、允许全部方法和头、不带 credentials。前端和网关均无需处理跨域。当前为开发口径全放开；上线前如需收敛到具体 origin，由 A 改一处即可。

## G5/G6/G7：summary / reset / topic

现状**没有** summary、reset、topic 这三个接口，请勿按「已存在」对接：

- **summary**：最接近的是 `POST /session/{id}/debrief`，响应形状为 **HTTP 202 + `{"status": "accepted"}`**（异步受理，不返回总结内容）。复盘/总结内容本轮不出接口；教练建议 `coachAdvice` 按 P15 只保留前端折叠占位。
- **reset**：无重置接口。「重新开局」= 重新 `POST /session` 拿新 session_id，响应**直接返回初始全量状态投影**，因此开局后**不需要**再 `GET /state`。旧会话不清理，随服务重启自然失效。
- **topic**：无会话内议题切换接口。议题/场景在开局 `POST /session` 请求体中确定（`scenario_id` + `agent` + 可选 `scenario_path`），会话内不可换；换议题 = 重开一局。
- 统一口径：凡成功响应（开局、action、auto_step、state）均为**同一个全量投影形状**，前端始终整棵替换，不做增量合并。
