主循环 · 每回合怎么推进

三种驱动方式共用同一条服务端流水线；一次请求 = 我方一手 + 对手一手
① 人工一手
看条款板 → 选策略卡 → 改条款取值 → 写公开发言 → POST /action（带 client_action_id + base_version）
② 自动推演
POST /auto_step：我方按规则出手 + 对手模型回应；一步一落盘，/auto_status 看 paused / running / done / error
③ 中途接管
POST /takeover：把 running 置回 paused，从自动切回人工
三条路汇到同一段服务端逻辑 ↓
A · 我方一手入账
契约校验（schema → 卡牌归属 / 冷却 / 载荷 → 行动点 → 条款名与取值合法）→ 引擎结算（红线只查行动方，不替对手守牌）→ 写公开事件、版本与报价板更新
B · 对手一手回击
输入 = System Prompt + 全部历史 + 本轮条款板 → 输出一个行动 + 一段发言 → 引擎校验（被拒则带条款板做纠正提示、重试 1 次；仍失败才报错并保留 engine_error）
C · 落盘 → 返回新状态
先写会话记录再返回；超时 / 失败时本轮零推进，可用同一 action_id 幂等重试
出错分支（对外只有 6 个码）： 400 INVALID_ACTION · 409 VERSION_CONFLICT（对方刚改版）/ SESSION_BUSY（上一轮还没完）/ ROUND_LOCKED（已终局）· 503 MODEL_UNAVAILABLE · 504 TIMEOUT
本回合手数用完 /
已可接受 / 已终局？
否 → 继续同一回合
再出一手
action_points_left 递减，回到"选驱动方式"
是 → 进入下一回合
next_round
行动点重置；若终局条件已成立直接跳到 03

终局 · 引擎裁定

不接受模型自判，五选一
终局五态
FULL_AGREEMENT 完整协议
PARTIAL_AGREEMENT 部分协议
WITHDRAWAL 主动退出
DEADLOCK 僵局
ROUNDS_EXHAUSTED 回合耗尽
终局后再提交
409 ROUND_LOCKED（engine_error = PHASE_CLOSED），会话冻结、不再推进

复盘 · 只有终局后才开

同步二态接口，没有"生成中"
POST /session/{id}/debrief
→ { debrief, evaluation }：协议质量 · 是否优于 BATNA · 学习评分 · 关键决策节点（他方私牌一律置 null）
未终局就调
409 DEBRIEF_NOT_AVAILABLE（fail_reason：谈判尚未结束，复盘暂不可用）

分支与对比 · 接口已通，但还没有界面
