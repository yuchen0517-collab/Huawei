# Task A · B1 证据点击跳转（唯一改交互的一步）

## A1 渲染层加锚点

改 `src/components/coach.js` 的 `evidenceList()`，让每条 evidence 变成可点击元素：

- 加 `data-act="coachEvidence"`
- 带 `data-round`（evidence.round）
- 带 `data-clause`（evidence.clause，可为空；为空时不写该属性）
- 带 `data-ev-kind`（action / offer / event）
- 保持 `R{n}` 前缀与 `label` 文案**完全不变**，视觉上只加 hover 下划线，不加按钮样式、不加图标
- 保留 `<span>` 结构，改为 `<button type="button" class="coach-ev-i">`，并补 `aria-label="定位到 R{n} {label}"`

## A2 对话视图加轮次锚点

在 `src/components/stage.js` 的对话视图里，给每条消息容器加 `data-round="{round}"`
（已有同名属性就复用，不要重复加）。若当前对话视图没有任何 per-round 容器，则在渲染时按
`state.actions` / `state.timeline` 的轮次分组补上，**不要新增数据结构**。

## A3 事件处理

在 `src/app.js` 的 `bind()` 里加一个 case：

```
case "coachEvidence": D.store.gotoEvidence(t.getAttribute("data-round"), t.getAttribute("data-clause"), t.getAttribute("data-ev-kind")); break;
```

在 `src/store.js` 新增 `gotoEvidence(round, clause, kind)`：

1. `kind === "action"` 或 `"event"` → `setView("chat")`，等一帧后 `document.querySelector('[data-round="R"]')`
   （R 为传入的 round）滚动到可视区并加 `class="flash"` 1.2 秒后移除。
2. `kind === "offer"` 且 `clause` 非空 → `setView("board")`，定位报价板里对应条款行并加同样的 flash。
3. 两处都找不到目标 → **不报错**，`D.overlays.toast(null, "该轮记录已折叠，请展开对话查看")`。
4. 滚动与高亮必须是**纯 DOM 操作**，不得写入 `state.round / version / ap` 任何一项，不得改变草稿。

`flash` 样式加在 `src/styles/app.css` 对应区块：`outline: 1px solid var(--gold)` + 1.2s 淡出，
**不使用 animation/box-shadow**（本项目不做精致动画，手册 1.4）。

## A4 自测

1. 提交一轮 → 展开教练 → 点「R2 …」→ 视图切到对话且 R2 那条被高亮。
2. 点 `kind="offer"` 的证据 → 切回报价板且对应条款行高亮。
3. 手改 mock 让 `round` 指向不存在的一轮 → 只出 toast，控制台无红色报错。
4. 点击后 `DIPLOMAT.snapshot()` 的 `round/version/ap` 与点击前**完全一致**。

**停下来等确认。**

# Task C · 两个已知缺陷（各改一处，改动要小）

## C1 修 `inFlight` 挡住下一轮

`src/core/coach.js`：把单一 `inFlight` 布尔量改为**按 basis_version 记账**的集合：

- `pending = {}`，键为 `basis_version`；`request(s)` 只在 `pending[s.version]` 已存在时 return。
- 任何一条请求 settle（成功/失败/超时）都 `delete pending[key]`。
- 自动重试**最多 1 次**的规则保持不变；重试期间允许新一轮请求并行，**不要**用同一变量互斥。
- 保留 `GUARD_MS = 8000`、`RETRY_MS = 3000` 与现有降级文案，不要改超时策略。

自测：DEMO 选 `failed` → 提交 → 3 秒内立刻再提交一轮 → 第二轮仍能拿到教练结果（Console 无跳过）。

## C2 契约口径对齐（只改文档）

`docs/coach-contract.md` §1.6 的映射表加一段「实现口径（T6 现状）」：

> 前端当前**透传后端 snake_case**（`coach.basis_version` / `items[].ap_cost` / `items[].apply_hint`），

> `sanitize → store → 组件` 三处同时改动，与本轮 diff 混在一起不可评审。A 选定方案后如需统一命名，
> 单独开一次重构。

**不要**为了对齐文档去改 `coach.js` / `coach.js` 组件的字段名。
